# LTspice闭环验证：使用方法与证据边界

2026-09-14新增的独立实验页，不替换原有静态扫描或正式控制验收。

## 如何打开

在平台目录运行 `python -m streamlit run streamlit_app.py`，浏览器进入 http://127.0.0.1:8501 ，选择左侧“LTspice闭环验证”，或点击主页新增的入口。

1. 选择冻结负载场景、起始频率和幅度。第一次建议保留默认低幅设置。
2. 点击“新建会话”。配置保存后，侧栏修改只影响下一次新建会话。
3. 点击“执行下一轮真实LTspice反馈”，或“执行最多3轮（小规模检查）”。
4. 查看端口电压、电流、功率、相位，以及本轮测量产生的下一条指令。
5. 查看逐轮日志、SHA-256、网表及RAW路径；反馈表可下载为CSV。
6. 通过“恢复／查看已有会话”读取历史结果。达到轮数上限不等于通过稳态验收。

首次查看可直接点击“查看历史5轮反馈示例（不启动求解）”，查看已保存的真实反馈结果，无需重新计算。该示例达到5轮上限，不能直接追加；需要试验时新建独立会话。

计算期间不要重复提交或切换会话。单轮执行完可以不再点击继续；三轮批次结束后停止追加指令。程序没有实时急停按钮，断开浏览器也不等于停止正在执行的求解器。

## 实际反馈机制

Python生成当前频率、幅度 → LTspice批处理瞬态求解 → 读取真实RAW → 按时间积分提取端口测量 → Python保护判断／局部P&O → 保存下一条指令。

每轮从相同初态重算此前全部已执行指令及本轮指令，只使用最新区间作反馈。这样不需要在分段边界把电感、电容清零，也不使用仅保存直流偏置的方法近似储能状态。它不是求解器实时暂停／恢复接口，耗时和磁盘开销会随轮数增长。

下一轮的stimulus.json保存上一轮feedback.json的SHA-256，可检查“上一轮决策确实被下一轮执行”。历史控制CSV、解析模型的最优频率和未来扰动信息不参与本页控制决策。解析模型模块仅用于取得冻结电路参数。

## 指标与保护口径

- 端口电压：末200 μs内最大值减最小值，单位Vpp。
- 端口电流：同窗口对i²作时间积分后开方，单位RMS。
- 控制功率：同窗口平均 v(t)i(t)，即P_port；不是视在功率，也不是声功率。
- 端口相位：当前频率基波拟合后计算V/I相位；不是匹配输入相位。
- P_Rm：内部机械支路电阻耗散，仅作诊断，不参与本页寻优。
- 保护：最新区间划分50 μs窗口，使用其中最大窗口Vpp和Irms；发现硬越限后下一轮执行零幅并锁存。降额／渐升轮次冻结频率，不同时改变频率和幅度。
- 电压160 Vpp为用户边界；电流6 mA RMS、软阈值130 Vpp／5.5 mA RMS及其他控制数值是本项目假设值，不是器械额定值。
- 前3 ms为建立段，RAW中保留但未纳入反馈保护统计。因此不提供包括启动在内的全过程安全结论。

保护在一轮求解结束后才响应，不能撤销此前已经发生的越限；50 μs非重叠窗口也不构成对所有滑动窗口／瞬时量的严格上界。当前页面绝不宣称160 Vpp在全过程绝不超过。

## 已执行验证

真实三轮联算：`results/ltspice_closed_loop/CL_20260914_112350_f3ffea20/`。

| 轮次 | 实际执行频率MHz | 幅度a | RAW平均端口功率mW | 下一频率MHz |
| --- | --- | --- | --- | --- |
| 1 | 0.8990 | 0.4 | 14.697 | 0.8995 |
| 2 | 0.8995 | 0.4 | 22.514 | 0.9000 |
| 3 | 0.9000 | 0.4 | 27.187 | 0.9005（未执行） |

该检查使用1 ms反馈区间，验证真实求解、测量和因果指令链，不证明寻优收敛。默认网页使用2 ms，与旧版20 ms准稳态控制周期不同。每轮真实求解约13–20秒，不能把计算机耗时当电路响应时间。

`tests/test_ltspice_closed_loop.py`的6个单元测试通过，覆盖反馈反向、软保护、硬停机锁存、保持、渐升、频率边界及零幅分支；这些是合成测量输入的程序测试，不是真实LTspice越限试验。

网页按钮另实际执行一轮2 ms反馈：`CL_20260914_113109_ef83fe74`，LTspice返回码0、求解约17秒；末窗口约59.46 Vpp、2.156 mA RMS、14.697 mW，产生下一频率0.8995 MHz。原始日志和`web_feedback_screenshot.png`同目录保留；截图是网页界面，不是LTspice GUI窗口。

首次取值失败记录保留在`CL_20260914_112140_276923f2`：RAW时间偏移与绝对测量窗口不匹配。现已改为保存完整历史时间轴，并处理RAW Offset；失败结果不计作通过。

## 未完成／不能据此声称

- 当前会话内负载固定，仅提供基准和fs−5%两种起始场景，不包含运行中的负载突变。
- 简单固定步长局部P&O并不保证全局最大功率，也没有正式连续稳态验收。
- 不是原计划固定／周期扫频／相位闭环的统一对比，更不能据此替换旧综合表。
- 幅度渐升／降额不是独立PI；没有反射硬上限、声学约束或真实硬件保护。
- 本次没有新增LTspice GUI截图。保留的.cir/.raw/.log是求解证据，网页截图只是界面运行证据。
- 未证明瞬态结果在各指令切换点都接近准稳态预测；那需要另做时间对齐及误差统计。

## 复现与原始文件

```powershell
python -m unittest discover -s tests -p test_ltspice_closed_loop.py -v
python scripts/verify_closed_loop_smoke.py
```

第二条命令会真实运行LTspice并创建新证据目录，约需一分钟及数百MB空间；并非只画示意图。

每个会话：config.json、session.json。
每轮：circuit.cir、circuit.raw、circuit.log、stimulus.json、execution.json、windows.json、feedback.json。
运行出错停止，不使用Python解析结果回填成LTspice结果。
