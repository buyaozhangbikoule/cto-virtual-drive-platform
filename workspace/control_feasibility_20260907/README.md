# 控制恢复流程可行性验证：第一轮

本轮只验证保护一致性及重扫顺序，不声称已复现任何文献算法，不覆盖或发布替换正式平台结果。

## 预先规定的试验

1. E00：冻结现有脚本、元件参数、校准和历史数据，重新执行原始控制器，逐字段核对历史时序。
2. E01：统一所有扫描/试探点的保护接口、同步实际幅度、显式记录低幅准备及选频动作、限制恢复升幅；保留旧的保护后在旧频率恢复的次序。
3. E02：完全保留E01的保护和动作成本，只改变保护恢复后的调度：安全保持结束后允许低幅重捕获，选频后恢复幅度。
4. 主测试每段0.8 s；补充测试每段1.6 s。三个版本、三种策略均使用同一对应时序。补充测试不能替代主测试。

保留160 Vpp/6 mA RMS硬限、130 Vpp/5.5 mA RMS软限、20 ms控制周期、60 ms硬保持、100 ms恢复保持、100 ms软稳定时间、0.05/控制周期恢复增量、原扫描窗口和网格。上述除用户明确电压及频段外均为假设控制设置，不是硬件安全额定值。

原验收保持不变：CONTROL、NORMAL、频率控制未冻结、捕获率≥98%，连续10个样本，控制样本间隔≤30 ms。另输出第10个样本的确认时刻，避免把第一次达标误写成已验收。

同时报告全部动作积分电能、扫描成本、记录点越限，以及在采样间隔内保持上一指令时遇到扰动的准稳态重放越限。两种越限口径必须分开。没有噪声、真实执行延迟、储能瞬态或硬件实验。

电学安全参考采用既有软限约束最优P_Rm；无C0介质损耗的当前模型中P_port=P_Rm。Gamma仅监测，不作为本轮硬约束。相位仍为匹配网络输入相位arg(Zin)。

## 已完成结果及复现方法

正式查看 `deliverables/第一轮仿真验证报告.md`；图像提供PNG、SVG、PDF三个格式。数值来源为 `results_r1`，不要混用开发初稿 `results`。

为避免覆盖证据，在原项目目录结构下运行 `python rerun_in_new_folder.py`：它会新建同级时间戳目录，重跑18条控制时序及独立检查，并逐字节比较所有结果CSV。该入口需要原始项目输入未被修改，不是脱离项目目录的一键部署程序。它不重新运行LTspice。

`run_experiments.py` 和 `validate_experiments.py` 是本次实际执行源码，不要在本证据目录直接重跑覆盖历史输出。LTspice重跑也应在新的工作副本中进行；可执行文件路径为 `D:/LTspice.exe`。图像可用 `python make_report.py` 从已存数据重新生成，不改变原始时序或RAW。

`ltspice_ac_verification` 保留12组真实`.cir/.raw/.log`和误差表。`evidence_manifest.json`记录最终打包文件的SHA256；ZIP不含早期开发草稿。
