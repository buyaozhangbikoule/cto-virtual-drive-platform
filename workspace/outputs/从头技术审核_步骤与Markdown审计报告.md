# 从头技术审核：BVD扰动、扫频选点与控制策略

审核日期：2026-08-11

## 一、总判定

整体研究路线是合理的：先建立基准电学模型，再做单因素扰动、比较选频准则、实现控制策略，最后统一比较。现有工作也确实调用过 LTspice，不是凭空生成数字。

但是，当前成果只能分层验收：

| 部分 | 审核结论 | 是否可继续引用 |
|---|---|---|
| 基准 BVD/L 型匹配的线性 AC 模型 | 有条件通过 | 可作为“假设参数下的虚拟电学模型”引用 |
| 第二步单因素扰动的数值结果 | 通过内部一致性审核 | 可引用，但必须保留模型边界和指标定义 |
| 第三步“三个最佳频率不一定相同” | 核心结论通过 | 可引用，但相位零点并不唯一，扫描耗时尚未实测 |
| 第四步控制比较 | 不通过“正式控制器验收” | 只能称“基于静态 RAW 频响表的准静态原型比较” |
| 第五步综合表 | 暂不通过最终验收 | 继承了第四步的协议和指标问题，需重算 |
| 已交付 Markdown 文档体系 | 内容多数有边界意识，但版本管理不通过 | 需建立唯一入口并标记历史版本 |

最重要的结论不是“以前结果都是错的”，而是：**电路计算与 LTspice 数据基本可信；第四、第五步把理想查表结果写得过于接近真实闭环验收，证据强度不够。**

## 三、必须优先整改的问题

### P0-1：第四步不是 LTspice 瞬态闭环

LTspice 实际执行的是每个扰动状态的 AC 扫频，得到静态频响 RAW。控制器随后由 Python 对 RAW 表插值查表。模型中没有：

- 电气/机械瞬态和建立时间；
- 扫频点的驻留时间；
- 频率切换时间、测量延迟和计算延迟；
- 噪声、相位测量误差和频率量化；
- 功放幅度/频率斜率、保护动作和重新启动过程。

因此“恢复 0 步”“18.28 步”等只能表示离散算法步数，不能称为实际恢复时间。第四步标题应改成“准静态控制原型比较”，除非补充动态模型或硬件在环实验。

### P0-2：周期扫频获得了理想化的即时重捕获

代码在每个状态切换的 `local_step=0` 立即完成局部扫频，然后才记录该步结果；201 个左右的扫描测点被视为一次瞬时动作。扫描期间经过的频率、功率、电压和电流完全没有计入时序或约束统计。

此外，每个状态固定驻留 20 步，周期扫描每 5 步一次，扰动边界恰好全部与扫描时刻对齐。即使删除“状态切换时强制扫描”，这种同步关系仍会给周期扫频不现实的优势。

所以当前的“平均恢复 0 步、最差功率捕获 99.97%、零约束触发”是理想上界，不是公平闭环结果。

整改要求：扰动时刻与扫描周期错开或随机化；先记录扰动后的测量，再执行控制动作；把每个扫描点的驻留时间和约束纳入时序。

### P0-3：相位控制器的固定符号在部分相位零点附近是正反馈

现有相位曲线不是单零点。LTspice RAW 显示，基准场景在 0.84–0.96 MHz 内有三个输入相位零点：

```text
0.887692 MHz, 0.899997 MHz, 0.915350 MHz
```

其中靠近 0.9 MHz 的零点局部斜率约为 `-4.68 deg/kHz`。现有规则

```text
f[k+1] = f[k] + Kf*(0 - phi[k]),  Kf > 0
```

在负斜率零点附近会形成正反馈。以 `Kf=100 Hz/deg` 线性化，局部误差倍率约为：

```text
1 - Kf*dphi/df ≈ 1.468
```

因此该零点理论上不稳定，控制器会被推向其他相位零点。现有结果不能证明“所有相位跟踪都很差”，只能证明“固定目标 0°、固定增益符号、未识别相位斜率和多零点的朴素控制器不合适”。

整改要求：启动扫频时记录目标功率点及目标相位；估计局部 `dphi/df` 的符号；使用带斜率归一化的更新、扰动寻优或功率梯度校正；明确零点选择和锁定盆地。

### P0-4：“功率恢复率”使用了容易误解的分母

第四步的功率捕获率定义是：

```text
P_operating / Pmax_of_current_disturbance_state
```

它衡量的是“选频是否接近该场景自身可达到的峰值”，不是“是否恢复到基准功率”。周期扫频报告的 99.99% 不表示恢复了 99.99% 的基准 125 mW。

按同一时序重新换算为 `P_operating / Pmax_baseline`：

| 策略 | 全时序平均基准功率保持率 | 最低基准功率保持率 |
|---|---:|---:|
| 固定频率固定幅度 | 81.70% | 10.44% |
| 周期性局部扫频 | 90.07% | 46.30% |
| 相位误差离散跟踪 | 46.37% | 3.03% |

周期扫频仍是三者中最好，但它不能恢复由 `Rm`、ESR 等引起的峰高损失。以后必须同时报告：

1. 场景内峰值捕获率 `P/Pmax,state`；
2. 基准绝对功率保持率 `P/Pmax,baseline`；
3. 实际功率 W/mW。

### P0-5：硬约束只被统计，没有被执行

旧控制规范写的是达到 160 Vpp 或 8 mA 后硬停止，正式脚本却只记录触发标志并继续运行。现有最大换能器端电压为：

| 策略 | 最大 Vpp | 场景 | 160 Vpp以上步数 |
|---|---:|---|---:|
| 固定频率固定幅度 | 181.10 Vpp | `fs -5%` | 40 |
| 周期性局部扫频 | 118.45 Vpp | `Rm +50%` | 0 |
| 相位误差离散跟踪 | 194.74 Vpp | `Cp -10%` | 127 |

如果 160 Vpp 被定义为硬限值，越限后的功率、收敛和振荡数据不能继续当作正常运行结果。必须实现限幅/停机/恢复状态机后重新统计。

## 四、第二步单因素扰动审核

### 合理且可保留的部分

- 每个非基准场景只主动改变一个登记参数；设计思路正确。
- `C0、Rm、fs、Rs、Ls、Cp、Q/ESR` 覆盖了主要电学敏感因素。
- 固定源相量、统一 BVD 端总峰值电流口径、运动支路有功功率定义前后一致。
- 同时输出 FWHM 和 95% 峰宽；趋势表使用 FWHM，比只用 95% 峰宽更合理。
- 解析模型与 LTspice RAW 的数值一致性通过。

### 需要收紧的解释

1. `fs` 扰动只通过改变 `Cm` 实现，不能把结论直接写成“Lm/Cm/fs 都一样”。改变 `Lm`、改变 `Cm`、按比例同时改变二者并保持某个 Q 或阻抗尺度，物理含义不同。
2. 电感 Q 被实现为“按 0.9 MHz 计算的固定串联 ESR”。扫频时 ESR 不随频率变化，因此是“Q 在 0.9 MHz 的标称值”，不是全频段恒定 Q。
3. 趋势标签“很小/明显/很明显”的阈值是人为设置的，而且各参数扰动幅度不等：例如 `Rm +50%`、`fs -5%`、`Q 100→20`。这些最大变化不能直接用于跨参数的因果重要性排序。应增加归一化灵敏度和单调性检查。
4. `C0` 只有 1.5 pF，而并联匹配电容约 248 pF；`C0 +30%` 只增加 0.45 pF。因此“C0影响很小”主要是当前拓扑和尺度的结果，不是一般规律。
5. `Rs` 扰动时反射代理的参考阻抗也随 `Rs` 改变。固定 0.9 MHz 负载输入阻抗其实不变，但报告中的反射代理从 0.0659 变为 0.0183 等。若目标是标准 50 Ω 端口 S11，应固定 `Z0=50 Ω`；若目标是与变化后的 Thevenin 源匹配，应另列“源匹配代理”，不要混用。
6. “峰位、峰高、峰宽”当前指运动支路有功功率峰，应在每张表头明确；它不是声功率峰。

结论：第二步可保留为当前模型的敏感性实验，但不能凭最大变化表直接宣布普遍的参数重要性顺序。

## 五、第三步扫频选点审核

核心问题设置是正确的，而且高组合场景确实证明最大功率点、相位点和最小反射点可以相差约 37.6 kHz。这个结论可保留。

需要补充：

- “最小绝对相位点”可能有多个并列零点。当前算法选择最接近 0.9 MHz 的零点，这是额外的中心频率先验，不是由“最小绝对相位”准则唯一决定。
- 第三步报告的 LTspice 专项复核只重跑了基准和高组合两个场景；其他场景当时由解析模型生成。第四步后来为全部 24 个唯一场景生成了 0.1 kHz RAW，可用于补齐第三步的全场景 RAW 复核。
- 0.01 kHz 参考网格是解析模型数值参考，不是真实频率标定精度。
- “扫描耗时”现在只是测点数代理。没有每点驻留、切换、采样和计算时间，就不能换算实际毫秒或秒。
- 推荐采用粗扫加细扫，而不是长期每次扫 401 或 2001 点；并在候选点靠近窗口边缘时触发扩窗。

## 六、第四、第五步指标审核

### 扰动时序不适合做单独恢复性能归因

当前顺序从 `C0 +30%` 直接切换到 `Rm +15%` 时，C0 恢复基准且 Rm 同时改变；相邻类别切换往往一次改变两个参数。若要比较每种单因素扰动的恢复时间，应采用：

```text
baseline → disturbance A → baseline → disturbance B → baseline ...
```

或使用随机但预先固定的连续时间序列，并明确每次状态变化的参数向量。

### “功率稳定性”定义不正确

第五步的功率稳定性是把全 500 步的功率捕获百分比混在一起求标准差。它同时包含不同场景、瞬态和稳态，不能单独表示稳态波动。应改为每个状态最后 N 步的标准差，再汇总平均值和最坏值。

### “峰值过冲”命名不正确

当前“峰值过冲”实际是全时序最大绝对功率峰频率误差，不是控制理论中的过冲。应改名为“最大瞬时功率峰频率偏差”，或真正计算相对于新稳态频率/功率的超调量。

### 约束触发应统计事件而不只是步数

当前触发次数是越限步数，结果随采样周期和驻留长度线性变化。应同时报告越限事件数、持续时间、最大越限幅度和保护结果。

## 八、文献引用审核

旧知识地图和讲义的大多数边界性陈述有合适来源支持：

- EAPCI CTO 共识支持以症状、缺血/心肌活性、风险和多学科决策评估血运重建，而不是“发现 CTO 就开通”。
- CCTA/J-CTO 文献支持钙化、纤维成分、长度和形态与导丝通过难度/PCI 成功相关，但这些是关联研究，不能直接转换成 BVD 参数。
- 40 MHz angled-aperture 文献确实是 FL-IVUS 成像可行性，不是治疗性超声疗效证据。
- HIFU 电功率监测文献支持同步电压、电流比仅监测电压更可靠，并明确声功率仍需效率与声学标定。
- 水听器综述支持高强度场中的非线性、空间平均、校准和损伤风险。

需要修订两点：

1. `arXiv:2405.12966` 应显式标注为预印本/原型研究，不能与临床或同行评议证据同等级呈现。
2. “优先拟合完整复阻抗实部和虚部”应补一篇直接使用复阻抗/复导纳拟合 BVD 参数的来源；当前 PMID 33465595 不能单独充分支撑这句话。

## 九、建议的重做顺序

1. **建立唯一模型入口。** 固定当前拓扑、参考面、参数版本、源幅口径、Z0、功率和电流定义；旧未匹配版本全部标记为历史。
2. **保留第二步数值，补方法学。** 增加归一化灵敏度；分别做 `Lm`、`Cm`、保持 Q/阻抗尺度的纯频移；同时输出固定 50 Ω 反射代理和源匹配代理。
3. **补第三步全场景 RAW 选点。** 枚举全部相位零点、局部斜率和功率；使用粗扫+细扫；只在定义每点时间后讨论扫描时间。
4. **重写控制仿真时序。** 测量在前、控制在后；扰动与扫描不同步；扫描点逐点占用时间；所有策略使用相同传感器信息和同一事件检测条件。
5. **实现保护状态机。** 软限幅、硬停机、频率撞限、重捕获和恢复逻辑必须真正改变后续状态。
6. **公平实现相位策略。** 目标相位来自最近一次功率扫频；识别 `dphi/df` 符号；处理多零点；再做 Kf、死区和最大步长扫描。
7. **重做第五步。** 同时报告场景内峰值捕获、基准功率保持、绝对功率、实际/模拟时间、稳态抖动、真正过冲、保护事件和扫描能量/时间开销。

## 十、当前可安全使用的结论

现在可以写：

> 在当前假设 BVD 与固定 L 型匹配网络的线性稳态 AC 模型中，LTspice 与解析计算一致。单因素扫描表明，在已选扰动范围内，`fs/Cm` 对功率峰位最敏感，`Rm` 和匹配网络损耗主要影响可达到的峰高与带宽。高组合扰动下，最大运动支路有功功率点、最近 0.9 MHz 的输入相位零点和最小反射代理点明显分离，因此不能把零相位普遍等同于最大功率。

现在不能写：

> 周期性扫频已经实现零步恢复；相位跟踪普遍只能恢复约49%功率；三种控制器已经在真实 LTspice 闭环或硬件条件下完成正式验收。

后一句必须等第四、第五步按上面的公平时序和保护逻辑重做后才能判断。
