# 本目录 CSV 的约束口径说明（2026-09-15 补记）

## 问题

本目录下的 `stage3_initial_three_criteria.csv` 等结果**产生于施加 V/I 约束检查之前**，
表中没有任何越限标注。计划书第 3 周明文要求：

> 「设定电压、电流和功率的相对上限，作为**控制器不得越过的模型内部约束**。」

在 `amplitude = 1` 下复核这些历史结果，三种准则选出的工作点越限情况为：

| 准则 | 越 160 Vpp 硬上限 | 最大电压 | 约束内可交付功率均值 |
|---|---:|---:|---:|
| 最大有功功率 | **0/34** | 119.6 Vpp | **143.9 mW** |
| **最小绝对相位** | **30/34** | **198.0 Vpp** | **6.6 mW** |
| 最小反射代理 | 2/34 | 188.3 Vpp | 137.8 mW |

最极端的 `CASE_CMATCH_M10`：最小相位准则选出 198.0 Vpp / 0.08 mW 的点，
而同场景最大功率点是 130.2 mW。

## 这不是运行期安全问题

已核实：**没有任何已实现的控制器按「最小相位」或「最小反射」选频。**
`run_stage4_5_control.py` 的 `local_scan` 三级扫描全部按
`normalized_port_power_W`（端口有功功率）选点，并且保护层会在越限前限幅 ——
五种策略共 2878 个控制样本，实际硬越界 **0 次**。

因此这是**报告口径问题**：直接引用本目录的表去做幻灯片或结论，
会把越界点当成有效选点呈现。
