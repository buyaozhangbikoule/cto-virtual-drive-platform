## 三、请优先攻击这些点

按我自己判断的风险排序。每条都给出我的理由和我做过的验证，请独立复核。

### 3.1 `limit_probe` 不改状态机，这个取舍对不对

它只做限值裁剪，不走 `apply()`。我的理由写在 2.1 第 1 条。
**但它也因此不检查 HARD_TRIP 与 RECOVERY_HOLD。** 我的依据是扫描只能在
`tracking_allowed()` 为真时启动，而该函数要求状态为 `NORMAL` 或已稳定的 `SOFT_FOLDBACK`，
所以扫描期间不可能处于 HARD_TRIP。**请复核这个不变量在所有路径上都成立**，
特别是扫描过程中时间推进、被控对象随日程切换之后。

### 3.2 端点检测的边界条件

```python
at_band_limit = ((index == 0 and abs(grid[0] - F_MIN) < EDGE_TOLERANCE_HZ)
                 or (index == len(grid) - 1 and abs(grid[-1] - F_MAX) < EDGE_TOLERANCE_HZ))
on_edge = index in (0, len(grid) - 1) and not at_band_limit
```

`EDGE_TOLERANCE_HZ = 1.0` 是我拍的。请检查：栅格只有 1 个点时 `index` 同时是 0 和 `len-1`；
`np.arange(lo, hi + 1, step)` 的 `+1` 在 step 为 0.1e3 时是否可能多出或少掉末点。

### 3.3 `max(measured)[1]` 的并列处理

`measured` 是 `(power, frequency)` 元组列表，`max` 先比功率，功率并列时取**更高的频率**。
这是一个未声明的偏置。我查过 21 点粗扫栅格在 BASELINE、QM_1000、LM_P20 上都没有重复功率值，
所以现批次不受影响，**但这是数据巧合不是保证**，加入噪声后会经常并列。

### 3.4 `scan_converged` 的回填方式

```python
first_row_index = len(rows)
...
for row in rows[first_row_index:]:
    row["scan_converged"] = int(converged)
```

依赖「本次扫描期间没有别的代码往 `rows` 里追加」。当前成立，但这是隐式耦合。

### 3.5 浮点时间累加

`t += CONTROL_DT` 反复累加，第 320 个样本落在 6.3999999999999515。
`schedule_at` 用 `int(t / SEGMENT_DURATION)` 分段，所以段边界会漂移约 5e-14 秒。
本轮规模下无害，**但它已经造成过一次误判**：我按 `time < 6.4` 筛选比对时，
`FIXED_0P9` 多出一行，看起来像轨迹分歧，实际只是这个边界效应。请确认没有别的地方被它影响。

### 3.6 `ScanCurveReference` 的幅度归一化假设

扫描在探测幅度 0.40 上取，控制样本在幅度 1.0 上取，靠 `p_port / a²` 对齐。
**线性模型里精确成立，真实器件不成立。** 这是整个扫描曲线参考方案最脆弱的前提。
另外 `np.interp` 在范围外会钳位，我加了范围检查返回 `NO_REFERENCE`，请复核该分支。

### 3.7 去嵌公式的可测性边界

`motional_phase_deg` 要除以 `i_source`，硬跳闸时它精确为零。
我加了 `MEASUREMENT_FLOOR_AMPLITUDE = 1e-6` 的可测性判据，两种信号一视同仁。
请检查：`RECOVERY_AMPLITUDE = 0.25` 远大于该阈值，所以只有幅度精确为 0 的 HARD_TRIP 会被判为不可测，
这是否是想要的粒度。

### 3.8 消融脚本对平台模块的 import 依赖

`run_phase_hold_ablation.py` 从 `run_stage4_5_control` import 了
`local_scan`、`Protection`、`ObservableDisturbanceDetector`、`SCHEDULE` 等。
**这意味着它与补丁强耦合**：没打补丁时 `local_scan` 的签名与返回值不同，第三个返回值语义也不同。
脚本没有对此做版本检查。请评估是否需要加一个断言。

## 四、我自己已发现并修掉的问题，不必重复查

1. **补丁误打进 `workspace/`**。已还原并按清单核对，补丁头已改为不可能误伤的形式。见第一节。
2. **`Protection.apply()` 不能用于探测点**，会抹掉软折返。改用 `limit_probe`。见 2.1。
3. **除零**：去嵌除以 `i_source`，硬跳闸时为零。已加可测性判据。
4. **转换速率规则的阈值低于相位死区**：`closable` 在 383 / 1704 个样本上低于
   `PHASE_DEADBAND_DEG = 0.1`，即控制器认为误差太小不必动，规则却要求扫描。
   无噪声下不触发，**有噪声会造成扫描抖动**。已把阈值下限钳到死区，修正后为 0 / 1704，六个变体结果不变。
5. **BVD 拟合的非凸性**：Qm 几百使 100 kHz 窗口里只有 1 kHz 宽的峰，
   从标称参数出发的梯度拟合原地不动，误差恰好等于种子到真峰的距离。已改为用扫描测得的峰位做种子。
6. **零点计数重复计**：`diff(sign(x)) != 0` 会把恰好落在零上的样本数成两次。已改为
   `x[:-1]*x[1:] < 0` 加精确零计数。
7. **`wrong_lock_flag` 双向失准**：漏报「压根没收敛」，也误报锁定频率精确正确但尾窗含瞬态的段。
   已拆成两个标志，但**误报未根治**，见第五节。

## 五、已知但未修的限制，属设计取舍

1. **全链路无噪声、无量化、无执行延迟。** 所有捕获率都是无噪声上界。
   `detector_retuning_study.py` 里的噪声表是专门为回答检测器问题做的**离线**敏感性分析，
   闭环批次里没有噪声。表中 0.1% 与 1% 两个水平是我自己选的示意值，不是任何仪器指标。
2. **尾窗含恢复瞬态**导致 `wrong_lock_flag` 误报。根治要改尾窗定义，那会改变正式三策略的
   `steady_error_pct`，必须单独分步验收，本轮不做。
3. **粗扫 5 kHz 步长仍依赖响应单峰单调。** 边界自检解决的是窗口不够宽和失效不可见，
   不解决栅格不够密。全带保证找到峰需要约 400 点、600 ms。单峰性本身来自偏低的耦合系数
   `k_eff = 0.066`，**耦合系数改成真实值后本轮扫描结论必须重新验证**。
4. **幅度上界 `a ≤ 1` 未放开**，属口径决策，需先确认 a=1 是额定输出还是校准点。
5. **周期扫频的 0.5 秒定时器未改**。它是该策略 685 ms 反应预算里最大的一项，
   扫描曲线参考同样可以替换它，但那会改变正式三策略结果。
6. **去嵌依赖匹配网络与 C0 的设计值准确**，器件老化或 C0 估计有误都会引入误差，未做敏感性分析。
