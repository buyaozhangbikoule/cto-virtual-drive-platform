## 一、总评

**复核报告第 4 节的每一条纠正都成立，我逐条独立复算，没有一条可以反驳，包括数值。**
它抓到了 review/12 的一个实打实的代码缺陷（复算脚本的相位目标传错），
三处措辞过强，一处物理机理讲错，一处时间重复计算，以及一处把预登记行为当成缺陷。

它同时提出的修复顺序（A 事件语义与失败边界 → B 扫描数据一致性 → C 调度设计）是对的，
且顺序不能颠倒：**不先把"这次失败是谁的责任"分清楚，后面任何调度优化都在优化一个读不出来的指标。**

我按 A 与 B 落地了代码，C 只落地了它要求的相位覆盖诊断，没有改调度策略本身。

一句话结论：**补丁不提高控制性能（41.90% → 41.96%，仍 1/12），它把"扫描失败"这个数变得可读。**
改完之后，(周期 × 相位) 41 组网格里 **搜索失败为 0**——
被当成扫描算法失败报出来的，全部是保护抢占或被测对象在扫描中途变了。

## 三、代码改动

`review/patches/plan_three_strategy.scan_fault_taxonomy.patch`，
改 `controllers.py`、`metrics.py`、`config.json`、`tests/test_unified.py` 四个文件。
**没有改 `models/`，没有改任何验收门槛**（98%、10 连续样本、160 Vpp / 6 mA 硬限、
0.8 s 段长、功率参考与源标定全部原样）。

### 3.1 A：点测量返回结构化状态，不再只返回 `None`

`Executor.point` 原来对四种完全不同的情况一律返回 `None`：

```python
if self.time-point_start != self.cfg['scan_point_us']:
    return None          # 运行结束/驻留被截断
if not valid_measurement(m):
    return None          # 保护置零？还是数据坏了？分不出来
```

改为 `PointResult(status, measurement)`，四个状态：

| 状态 | 判据 | 含义 |
|---|---|---|
| `VALID` | 有效、NORMAL、未冻结、频率到位 | 可用 |
| `PREEMPTED_PROTECTION` | 无效**且** `m.frozen or m.state != 'NORMAL'` | 保护链在工作，不是扫描的错 |
| `INVALID_MEASUREMENT` | 无效**且**保护处于 NORMAL | 数据故障 |
| `END_OF_RUN_TRUNCATED` | 驻留被截断或运行已结束 | 谁都不是，不计账 |

判据只读**返回样本自身的**保护状态，不读被控对象真值、不读 `case_id`、不读日程。

`scan()` 的 `ScanResult` 增加 `status` 字段，`reason` 保持原样不动（旧日志阅读器不受影响）。
`status` 的默认值是 `SEARCH_FAILED`：**认不出来的失败一律算控制器自己的**，
不允许有失败逃出记账。

### 3.2 A：四类预算分开记账，但共用同一个锁存

```python
class ScanBudget:
    CLASSES = ('search', 'preemption', 'measurement', 'nonstationary')
```

复核报告特别强调"不能只是把失败计数删掉"，也强调已锁存的真故障必须保留显式复位规则。
落地时严格照办：

- 保护抢占不再消耗**搜索**预算，但有自己的上限 `scan_preemption_max_retries = 4`；
- 任何一类耗尽，都进入**同一个** `FAILED_SCAN_LATCHED_HOLD`；
- `ScanBudget.success()` 清 episode 计数，**不清 `exhausted`**——
  与 `config.json` 的 `failed_scan_exhaustion: latched_low_hold_until_explicit_run_reset` 一致。
  这一条是预登记行为，不是缺陷，我在 review/12 里原先的写法已改正。

失败时 `SCAN_FAILURE` 事件多带 `status`、`budget_class`、`episode_failures_in_class`、
`class_limit` 与四类累计数。`metrics.py` 增加 `scan_failures_search` /
`_preemption` / `_measurement` / `_nonstationary` 四列，原 `scan_failures` 列语义不变，
且断言四列之和等于它。

### 3.3 B：级间实测锚点复核

原来只有全部三级跑完之后才比一次末端锚点，因此**任何一级提前耗尽都会绕过这道检查**。
改为每一级结束都用 `io.point(trusted_frequency, ...)` 实测一次并与起始锚点比
（复用现成的 `changed_anchor`，即复归一化功率与复输入阻抗的相对差）。
最后一级那次沿用原来的 `SCAN_ANCHOR_END` 名字，中间两次叫 `SCAN_ANCHOR_LEVEL`。
每次复核都是真实执行的点，计入时间轴与保护，不是免费查询。

### 3.4 B：细级碰边先实测，再有界回退，不直接判"负载变了"

复核报告 3.2 的关键一句：**不能仅凭边缘最大值判断负载已变**——
真峰本来就在窗口外、多峰、噪声都会产生同样现象。落地逻辑：

```
某一级重定位预算走满
      ↓
实测锚点复核
      ↓
锚点变了 ────────→ NONSTATIONARY_SCAN（丢弃本轮全部候选，按非平稳预算重扫）
      ↓ 没变
level > 0 且回退次数未满 ─→ 回退一级、重置中心到可信频率，继续（有界）
      ↓ 否则
SEARCH_EXHAUSTED（真正的搜索失败）
```

同一条原则也补到了末端校验上：`FINAL_VALIDATION_FAILED` 之前先实测一次锚点，
锚点也变了就判非平稳，而不是把"候选复现不了"一律记成搜索失败。
这一条是重跑时才发现必要的——见第四节 7.2015 s 那次。

另加两个成本上限：`scan_max_points = 400`、`scan_max_duration_us = 300000`
（后者约为扫描周期的 60%，即一次扫描不得占用超过六成周期）。

### 3.5 常数取值

新增常数全部是**声明值，不是整定值**，`config.json` 里用
`scan_budget_origin` 字段写明了这一点：

| 常数 | 值 | 依据 |
|---|---|---|
| `scan_preemption_max_retries` | 4 | 无依据，仅取"大于搜索预算"以体现保护抢占不是控制器的错；上限本身必须存在 |
| `scan_measurement_fault_max_retries` | 2 | 与原搜索预算对齐 |
| `scan_nonstationary_max_retries` | 2 | 与原搜索预算对齐 |
| `scan_max_coarse_fallbacks` | 2 | 无依据 |
| `scan_max_points` | 400 | 无依据 |
| `scan_max_duration_us` | 300000 | 取 `scan_period_us` 的 60% |

**这些值的敏感性没有做，复核报告要求的"预登记与验证"只做到了预登记那一半。**
在做完敏感性之前，它们不应被当作推荐值。

### 3.6 测试

原 27 项**全部保留且全部通过**，新增 14 项，共 41 项。

只改了一项原测试：`test_truncated_probe_is_not_validated` 原来断言
`assertIsNone(result)`，`point()` 改了返回类型后改为断言
`result.status == 'END_OF_RUN_TRUNCATED'` 且 `ScanBudget.classify(...) is None`——
比原断言更强。

新增的 14 项全部是**强制走新分支**，因为这些路径在正常运行里不可达：
保护抢占、数据故障、截断不计账、未知状态回落到搜索预算、级间检出非平稳、
真实段边界跨越、平稳对象不误报、碰边回退且有界、成本上限、四类预算各自锁存、
抢占不吃搜索额度、成功清 episode 不清锁存、策略层分类上报并保持低幅、
指标四列拆分且合计不变。

上一轮已经有过教训（`failed_scans` 变量未初始化，因为分支不可达所以跑起来一切正常），
所以这次没有任何新分支是只存在于纸面上的。

## 六、模糊推测清单

1. **此处为模糊推测内容**：3.5 节那六个常数我认为"数量级合理"，但没有任何敏感性数据。
   它们可能显著影响失败后的恢复轨迹，进而影响达标段数。改动前不要引用它们。

2. **此处为模糊推测内容**：级间锚点复核用的 `changed_anchor` 阈值
   （`scan_validation_relative_tolerance = 0.1`）是沿用原值，没有为新用途整定。
   复核报告 6.B 第 2 点提醒过：低信号与噪声下不能无条件除以接近零的幅度与功率。
   现有实现按 `max(|Za|, 1e-15)` 与 `max(Pa, 1e-15)` 兜底，但这只是防除零，不是噪声模型。

3. **此处为模糊推测内容**：一个锚点没变**不能**证明整条频响没变——
   同一频点上不同参数组合可能近似等效。多锚点或时间新鲜度规则会更稳，但成本更高，
   本轮没有做成本对照。

4. **此处为模糊推测内容**：复核报告和我都认为真实器件上保护抢占会比本模型更频繁
   （真实漂移连续，本模型是 800 ms 一跳的阶跃）。这是判断，不是本模型能支撑的推断。

5. 本文全部结论只在这一套假设 BVD 参数、有损 L 型匹配、戴维南源的准稳态线性电学模型内成立。
   **未运行 LTspice、未做硬件实验、未做 COMSOL 或声场验证，也未证明真实电路瞬态全过程不越限。**
