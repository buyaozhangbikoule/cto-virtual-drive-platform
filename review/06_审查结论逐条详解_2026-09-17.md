## 一、三级扫描为什么是局部搜索

### 1.1 扫描是怎么工作的

`local_scan` 分三级，每一级都取自己窗口内观测功率的最大值，然后把它当作下一级的中心：

| 级别 | 窗口 | 步长 | 点数 |
|---|---|---|---|
| 粗扫 | 当前频率 ±50 kHz | 5 kHz | 21 |
| 精扫 | 粗扫最优 ±5 kHz | 1 kHz | 11 |
| 超精扫 | 精扫最优 ±1 kHz | 0.1 kHz | 21 |

共 53 点，每点驻留 1.5 ms，合计 79.5 ms。探测幅度 0.40，观测量是幅度归一化的端口有功功率
即 `P_port / a²`。

### 1.2 它为什么在多数场景能成功

成功依赖一个没有写出来的前提：**安全功率曲线在谐振附近是单峰且单调下降的。**

有了单调性，链条是闭合的：

1. 粗扫栅格间距 5 kHz，所以离真峰最近的栅格点与真峰的距离不超过半个步长即 2.5 kHz。
2. 单调性保证这个最近点就是粗扫的最大值。任何更远的点功率必然更低。
3. 精扫窗口是 ±5 kHz，一定覆盖得住这个 2.5 kHz 的误差。1 kHz 步长把误差压到 0.5 kHz。
4. 超精扫 ±1 kHz、0.1 kHz 步长再把误差压到 50 Hz。

第 1 步和第 3 步的前提都是**真峰落在粗扫窗口里**。这个前提一旦不成立，第 2 步的推理也随之失效。

顺带说明一个容易混淆的点：安全功率峰并不精确等于 fs。匹配网络会把峰往下拉一点：

| fs 漂移 | fs | 安全功率峰 | 差 |
|---|---|---|---|
| 0% | 900 000 Hz | 900 000 Hz | 0 Hz |
| −1% | 891 000 Hz | 890 900 Hz | −100 Hz |
| −3% | 873 000 Hz | 872 800 Hz | −200 Hz |
| −5% | 855 000 Hz | 854 790 Hz | −210 Hz |
| −7% | 837 000 Hz | 836 810 Hz | −190 Hz |

偏差只有一两百赫兹，对扫描讨论没有影响，但在写报告时不能把两者当同一个量。

### 1.3 失效机制：为什么恒定返回 844.0 kHz

真峰跌到 850 kHz 以下之后，失效是完全确定性的，可以逐级推出来：

```
粗扫窗口   = [900-50, 900+50] = [850, 950] kHz, 步长 5 kHz
           真峰在 850 以下, 曲线在窗口内单调递减
           -> 最大值必落在左边缘 850.0 kHz

精扫窗口   = [850-5, 850+5]   = [845, 855] kHz, 步长 1 kHz
           同理 -> 最大值必落在左边缘 845.0 kHz

超精扫窗口 = [845-1, 845+1]   = [844, 846] kHz, 步长 0.1 kHz
           同理 -> 最大值必落在左边缘 844.0 kHz
```

所以失效时返回值恒为 **844.0 kHz**，和真峰在哪无关。有效搜索下界就是
`900 − 50 − 5 − 1 = 844 kHz`，搜索半径 56 kHz。

注意这 56 kHz 比粗扫窗口的 50 kHz 还多 6 kHz，因为精扫和超精扫各自又往外探了 5 kHz 和 1 kHz。
这解释了为什么 fs 漂移 −6.0% 时峰在 846 kHz，仍然 100% 捕获，而 −6.5% 时峰在 841.3 kHz 就塌掉了。

### 1.4 悬崖在哪里

| fs 漂移 | fs | 安全功率峰 | 相对 844 kHz | 扫描返回 | 捕获率 |
|---|---|---|---|---|---|
| −5.0% | 855.0 kHz | 854.79 kHz | 界内 | 854.8 kHz | 100% |
| −6.0% | 846.0 kHz | 845.8 kHz | 界内 | 845.8 kHz | 100% |
| −6.5% | 841.5 kHz | 841.30 kHz | 出界 | 844.0 kHz | 6.39% |
| −7.0% | 837.0 kHz | 836.81 kHz | 出界 | 844.0 kHz | 1.00% |
| −10.0% | 810.0 kHz | 809.8 kHz | 出界 | 844.0 kHz | 0.06% |

这是一条硬边界，不是渐变。边界两侧只差 0.5 个百分点的 fs 漂移，捕获率从 100% 掉到 6.4%。

塌陷速度可以用洛伦兹线型核对。基线峰宽 FWHM = 1736 Hz，离峰 d 处剩余功率约为
`1 / (1 + (2d/FWHM)²)`：

| 离峰距离 | 实测占比 | 洛伦兹预测 |
|---|---|---|
| 500 Hz | 79.19% | 75.08% |
| 1 000 Hz | 40.59% | 42.96% |
| 2 500 Hz | 8.12% | 10.75% |
| 5 000 Hz | 2.10% | 2.92% |
| 10 000 Hz | 0.53% | 0.75% |
| 22 600 Hz | 0.10% | 0.15% |

最后一行正是 CASE_LM_P20 的情形：返回 844.0 kHz，真峰在 821.4 kHz，相距 22.6 kHz，
实测捕获 0.10%，洛伦兹预测 0.15%。量级一致，机制确认。

### 1.5 为什么失效不可见

这一点比失效本身更值得担心。**整条链上没有任何一处会报告失败：**

1. `local_scan` 每一级直接 `return max(measured)[1]`，不比较最大值是不是端点。端点命中这个事实
   在代码里根本没有被计算过。
2. 保护链不会报警。844 kHz 远离谐振，端电压和电流都很低，软限硬限都不触发。
   **保护链的沉默恰恰是失效的症状，却被当成正常。**
3. 扰动检测器在扫描结束后被 `after_scan()` 清空参考并进入冷却，
   所以它不会把「扫描后功率极低」当成新的异常。
4. 评价指标 `safe_power_capture_ratio` 确实会记录 0.1%，但那是**离线评估字段**，
   由日程和预计算最优点算出，控制器本身看不到，也不允许看。

第 4 点是个两难：检测器不偷看真值是本项目做得最好的设计之一（见 `04` 的 A3），
但正因为不偷看，它也就没有办法知道自己扫失败了。解决办法不是让它偷看，
而是给它一个**可观测的**失败信号，也就是 `05` 里提的 `converged` 标志。
端点命中是控制器自己能算出来的，不需要真值。

### 1.6 两个失败场景

34 个登记场景里只有两个失败：

| 场景 | 真峰 | 距 0.9 MHz | 扫描返回 | 捕获率 |
|---|---|---|---|---|
| CASE_LM_P20 | 821.4 kHz | 78.6 kHz | 844.0 kHz | 0.10% |
| CASE_CM_P20 | 821.4 kHz | 78.6 kHz | 844.0 kHz | 0.14% |

两者峰位相同不是巧合。`changed_lm_only` 把 Lm 乘 1.2，`changed_cm_only` 把 Cm 乘 1.2，
而 `fs = 1/(2π√(LmCm))`，两种改法对 fs 的影响完全一样，都是除以 √1.2。
所以 `900/√1.2 = 821.6 kHz`。它们只在 Qm 上不同：Lm 加大使 Qm 升到 876.4，
Cm 加大使 Qm 降到 730.3，于是峰宽不同（1133 Hz 对 1355 Hz），捕获率才有 0.10% 和 0.14% 的微小差别。

### 1.7 关于闭环日程的事实陈述

stage 4/5 的 `SCENARIO_ORDER` 是：BASELINE、C0_P30、RM_P50、FS_M5、LMATCH_P10、QL_20、
COMBINED_HIGH、BASELINE。LM_P20 和 CM_P20 都不在其中。

需要把话说准：**我没有证据说这是有意挑选。** FS_M5 是 fs 单因素族里漂移最大的一档，
COMBINED_HIGH 是组合族里最强的一档，选它们当最坏情况是自然的做法。
而 LM_P20 和 CM_P20 属于 Lm-only 和 Cm-only 族，这两族在计划书里的定位是「哪类扰动主要改变频率」
的诊断用途，不是压力测试主力。

但客观结果必须记录：**现有闭环结果从未触发过这个失效。** 所以「三策略在 7 个扰动段上表现如何」
这个结论，不能外推成「扫描策略在 34 个登记场景上都可靠」。补跑时必须把这两个场景加进日程。

### 1.8 真正的量级问题

即使修好了窗口，还有一件事要说清楚。峰宽范围是 1133 到 2778 Hz，工作频带 0.8 到 1.0 MHz 宽 200 kHz。
**要在全带内保证找到峰，栅格步长必须小于约半个峰宽即 500 Hz，需要约 400 点、600 ms。**

现在的 53 点、79.5 ms 在结构上就不可能是全局搜索。它之所以够用，是因为「起点离峰不远」加上
「曲线单峰单调」这两个前提同时成立。

`ltspice_closed_loop.py` 的元数据里其实已经写了
`Local power search is not guaranteed to find global optimum`。这句限定是对的，
但它没有进入 README、PPT 或状态文档，所以对外材料里扫描仍然读起来像是在找全局最优。

## 二、arg(Zin) 相位闭环为什么会锁错

### 2.1 这不是 bug，是拓扑决定的

L 型匹配网络的结构是串联 L 加并联 C：

```
源 -> Rs -> [r_L + jwL 串联] -> 节点 -> [C_match 对地] 并联 [BVD 对地]
```

远离换能器谐振时，机械支路 `Rm + j(wLm - 1/(wCm))` 是高阻抗，BVD 退化成只剩静态电容 C0。
在 0.9 MHz 上：

| 支路 | 阻抗幅值 |
|---|---|
| C0 支路 | 25 786 Ω |
| C_match 支路 | 623.6 Ω |

并联后由 C_match 主导，等效为两个电容并联即 `C0 + C_match = 290.46 pF`。于是

```
Zin ≈ r_L + jwL + 1/(jw(C0 + C_match))
```

这是一个串联 LC。它的零电抗点在

```
f = 1 / (2π √(L (C0 + C_match)))
  = 1 / (2π √(106.7258e-6 × 290.4569e-12))
  = 903 950 Hz
```

### 2.2 数值验证

用模型实际算出的 arg(Zin) 过零点，与上式预测对比：

| 场景 | 实测零点 | 公式预测 |
|---|---|---|
| CASE_FS_M3 | 904.6 kHz | 904.0 kHz |
| CASE_FS_M5 | 904.4 kHz | 904.0 kHz |
| CASE_LM_P20 | 904.2 kHz | 904.0 kHz |
| CASE_COMBINED_HIGH | 904.1 kHz | 903.8 kHz |
| CASE_COMBINED_MEDIUM | 902.8 kHz | 902.3 kHz |

吻合。COMBINED 两例预测值略有不同，是因为这两个场景的 L 和 C_match 本身也被扰动了。

### 2.3 为什么它不随换能器移动

关键在于公式里只有 `L`、`C0`、`C_match` 三个量，**Rm、Lm、Cm 完全不进来**。

换能器谐振跑到 855 kHz 还是 821 kHz，这个零点都稳稳待在 904 kHz 附近。
以 arg(Zin) 为误差信号的控制器会把频率推过去，相位误差收敛到零，
而此时功率捕获率是 0.03%。

这是一个**相位锁得很好、功率几乎为零**的稳态。它比发散更危险，因为所有相位指标都显示正常。
`run_phase_ablation.py` 里的 `wrong_phase_lock_flag`（相位误差 ≤ 0.5° 但捕获率 < 95% 即置位）
正是为了捕捉这个，说明作者已经预见到了。问题在于它目前只是消融脚本里的一个内部字段。

### 2.4 什么时候还能用

条件是扰动小到功率峰仍然贴着网络零点，即峰偏离 904 kHz 不超过约 1 kHz。

- **通过的 20 个**：C0 族、Rm 族、Rs 族、电感 Q 族、Qm 族，峰都还在 900 kHz 左右。
- **失败的 14 个**：fs 族、Lm 族、Cm 族、Lmatch 中高档、Cmatch 中高档、组合中高档。
  其中 13 个捕获率低于 0.2%。

也就是说：**凡是把谐振点推走的扰动，相位策略都失效；凡是只改变峰高峰宽的扰动，相位策略都没问题。**
而把谐振点推走恰恰是这个课题最关心的那类扰动。

### 2.5 零点个数是一个完美判据

统计带内 arg(Zin) 的过零个数：

| arg(Zin) 零点个数 | 场景数 |
|---|---|
| 3 个 | 20 |
| 1 个 | 14 |

对照机械支路相位：

| arg(Zm) 零点个数 | 场景数 |
|---|---|
| 1 个 | 34 |

而且零点个数**完全预测**相位策略成败。「arg(Zin) 有 3 个零点」与「arg(Zin) 跟踪达到 95% 捕获」
在 **34 / 34** 个场景上一致。

机制清楚：换能器谐振靠近网络设计点时，带内有三个过零，换能器自身的串并联结构贡献两个，
匹配网络贡献一个。谐振跑开后，换能器那两个离开频带或相互抵消，只剩网络那一个，
控制器就锁到它。

**实用价值**：捕获扫描本来就逐点测了电压和电流，顺便统计带内过零个数不需要任何额外测点。
只剩一个零点，就说明换能器谐振已经跑出频带或跑得很远，此时不应把频率交给相位控制器。
这是一个零成本的在线自检。

### 2.6 替代信号：机械支路相位

去嵌是可行且精确的。驱动器在功放端能测到输入电压和源电流，匹配电感、其 ESR、匹配电容、其 ESR
和 C0 都是已知设计值，所以机械支路可以解析剥离：

```
z_in       = v_input / i_source
z_parallel = z_in - r_L - jwL
v_port     = i_source * z_parallel
i_port     = i_source - v_port / z_cmatch
i_motional = i_port - jw*C0*v_port
arg(Zm)    = arg(v_port / i_motional)
```

原型验证：全 34 场景下，由上式还原的 arg(Zm) 与模型内部真值偏差在 **10⁻¹⁵ 到 10⁻¹² 度**量级，
即浮点精度。整个推导不读取 Rm、Lm、Cm。

它的好处是数学上的：`arg(Zm) = atan((wLm − 1/(wCm)) / Rm)` 对频率**严格单调递增**。
原型确认 34 个场景全部单调、全部恰好一个零点。**单调且唯一零点的误差信号不可能锁到错误点。**

它的局限也要说清楚：`arg(Zm) = 0` 对应的是 fs，而 fs 与受约束最大功率点在匹配网络失谐时并不重合。
所以直接追 arg(Zm) = 0 只有 26 / 34 达到 95%，最差的 CASE_LMATCH_P10 只有 81.6%。

**修法**：不追零，而是追「捕获扫描时记录下来的那个 arg(Zm) 值」。单调性保证这个非零目标唯一可达。
现 `run_phase_ablation.py` 对 arg(Zin) 已经是这么做的（目标取自基线最优点的实际相位 −1.078°），
只需把信号换掉，控制律不用改。

### 2.7 对计划书的影响

计划书把「基于相位误差的离散频率跟踪」列为第三个正式策略，与固定、周期扫频并列比较。

按上面的结论，**这个并列在本拓扑下没有意义**：相位不是一个能独立完成捕获的策略，
它只能做精修和保持。建议把正式三策略改成「固定 / 周期扫频 / 扫频捕获＋相位保持」，
把纯相位作为消融项保留，并把 `wrong_phase_lock_flag` 提升为一等评价指标。

## 三、三条需要补跑或补说明的

### 3.1 幅度被结构性钉死在 1.0

`allowed_amplitude` 的取小运算里第一项是全 1 数组：

```python
a = np.minimum.reduce([
    np.ones_like(unit["vport_vpp"]),          # <-- 上界 1，结构性的
    v_limit / np.maximum(unit["vport_vpp"], 1e-30),
    i_limit / np.maximum(unit["iport_irms_A"], 1e-30),
])
```

所以允许幅度上界是 1，这是代码结构决定的，不是物理约束。

实测 34 个最优点上它**全部精确等于 1.000000**。换句话说，软限 130 Vpp 和 5.5 mA
在任何一个登记工作点上都不起作用。它只在离谐振较远处收紧，全场景最紧到 0.656。

代价可以量化。如果允许幅度上探到软限：

| 场景 | 现在功率 | 端电压 | 允许幅度 | 放开后功率 |
|---|---|---|---|---|
| BASELINE | 170.0 mW | 100.0 Vpp | 1.100 | 205.7 mW |
| QL_20 | 113.1 mW | 81.6 Vpp | 1.361 | 209.6 mW |
| COMBINED_MEDIUM | 124.0 mW | 99.7 Vpp | 1.298 | 208.8 mW |
| COMBINED_HIGH | 72.6 mW | 81.1 Vpp | 1.602 | 186.3 mW |
| LM_P20 | 96.5 mW | 79.3 Vpp | 1.360 | 178.5 mW |

COMBINED_HIGH 掉到 72.6 mW 这件事，有 2.6 倍的恢复空间被结构性封住了。
而 `docs/01` 的下一步里同时写着「升幅的时间预算」和「独立幅度 PI」，这两件事在现模型里做不了。

**需要决定的是口径，不是改 bug**：a = 1 到底是额定输出还是校准点。
是校准点就放开并重跑全部控制批次；是额定输出就把「幅度不可上调」写进策略定义，
并从下一步清单里删掉幅度 PI。

顺带澄清一个容易误读的指标。三策略报表里 `actual_hard_violations = 0`，
这主要说明控制器待在谐振点附近，不等于保护链经受住了考验。真实触发只有 1 到 2 次，全在切换瞬态。

保护本身确有必要：基线在 a = 1 时，906.7 kHz 附近端电压会冲到 **187.75 Vpp**，超过 160 Vpp 硬限。
所以过压风险是真实的，但那是**频率过渡期**的风险，不是稳态工作点的风险。

### 3.2 扫描点不经过保护链

`local_scan` 三个阶段都把 `PROBE_AMPLITUDE = 0.40` 直接传给 `measure()`，
没有经过 `Protection.apply()`。控制样本走保护链，扫描样本不走。

量化现状：全 34 场景、全频带、100 Hz 栅格共 68034 个采样点上，
软限限幅器**一次也不会削减** 0.40 的探测幅度；最坏的「探测幅度 / 允许幅度」比值是 0.6099。
对应的最坏值是 79.28 Vpp 和 2.3865 mA，对 130 Vpp 和 5.5 mA 有充足余量。

所以历史批次确实没有越限。**但这是余量的运气，不是机制的保证。** 探测幅度一旦上调，
或场景扩展到更强失配，现结构会静默越限。`measure()` 里确实计算了 `actual_voltage_hard_violation`，
所以越限会被记录，只是不会被阻止。

计划书第 3 周原文要求「所有扫描／试探样本逐点进入同一保护链」。改动量极小。
而且正因为预期是空操作，改完后结果应当逐位不变，这本身就是一次现成的回归验证，建议排在第一个做。

### 3.3 Qm 族不是负载扫描

`bvd_from_fs_qm` 固定 Rm 和 fs，由 Qm 反推 Lm 和 Cm：

```python
lm = qm * rm / omega
cm = 1 / (omega**2 * lm)
```

于是在谐振点 ω = ωs 上：

```
z_m(ws) = Rm + j(ws*Lm - 1/(ws*Cm)) = Rm + j0 = Rm
```

虚部严格为零，与 Qm 无关。所以三个场景峰值功率完全相同：

| 场景 | 峰值安全功率 | FWHM |
|---|---|---|
| CASE_QM_500 | 169.999978 mW | 2778 Hz |
| CASE_QM_800 | 169.999978 mW | 1740 Hz |
| CASE_QM_1000 | 169.999978 mW | 1390 Hz |

数学上没错。但物理上 Qm 的变化正是辐射负载带来的，而**辐射负载同时改变 Rm 和 Qm**。
固定 Rm 单独改 Qm 对应不到任何一种真实的负载变化。

这一族应该改名叫「带宽敏感性」，或者重新设计成 Rm 与 Qm 同步变化的真正负载族。

## 四、物理层

### 4.1 脉冲还是连续波：最上游的选择

前视导管文献的治疗方式是 20 个 0.1 ms 脉冲、PRF 909 Hz，占空比 `0.1 / 1.1 = 9.09%`，
机理是微泡惯性空化。本项目是连续波准稳态，控制周期 20 ms。

高 Q 与短脉冲互斥，而且可以量化。谐振器的振幅时间常数是 `τ = 2Qm / ω`，
脉冲内建立的幅度比例是 `1 − exp(−t/τ)`，功率比例是它的平方：

**0.9 MHz：**

| Qm | τ | 0.1 ms 内幅度 | 0.1 ms 内功率 |
|---|---|---|---|
| 800 | 282.9 μs | 29.8% | 8.9% |
| 200 | 70.7 μs | 75.7% | 57.3% |
| 100 | 35.4 μs | 94.1% | 88.5% |
| 43.4 | 15.3 μs | 99.9% | 99.7% |

**1.85 MHz（文献器件工作频率）：**

| Qm | τ | 0.1 ms 内幅度 | 0.1 ms 内功率 |
|---|---|---|---|
| 800 | 137.6 μs | 51.6% | 26.7% |
| 200 | 34.4 μs | 94.5% | 89.4% |
| 100 | 17.2 μs | 99.7% | 99.4% |

要让 0.1 ms 脉冲建立到 95% 幅度，0.9 MHz 上需要 Qm 低于约 100，1.85 MHz 上需要低于约 200。

两条路各自都自洽，但它们要求不同的模型：

- **脉冲空化路线**：Qm 必须低。此时峰宽从 1.7 kHz 展宽到十几 kHz，
  前面那些窄峰跟踪的困难大幅缓解，但瞬态建立过程变成新的主要问题，**准稳态假设不再成立**，
  整套 20 ms 控制周期的框架要重新设计。
- **连续波热效应路线**：Qm 可以高，现框架适用。但对一根 1.55 mm 导管、在流动血液中、
  面对钙化斑块，热效应能否起作用是另一套论证，而且血流会持续带走热量。

现在的模型是「高 Q 加连续波」，在电学上完全自洽，但它没有对应到文献里那个器械。
**这个前提不在 `docs/01` 的待决策清单里**，建议最先确认，因为它决定上面所有算法工作是否对路。

### 4.2 参数量级

用 Janů 2021 论文的**最终迭代值**，不是线性化初值。该文明确说初值那组的曲线
「do not match」，只用作迭代起点：

| 量 | Janů 实测（最终值） | 本项目 | 比值 |
|---|---|---|---|
| fs | 39.95 kHz | 900 kHz | — |
| Rm | 1330 Ω | 7352.94 Ω | 5.5× |
| Lm | 0.2300 H | 1.0402 H | 4.5× |
| Qm | 43.4 | 800 | 18× |
| Cm/C0 | 0.0304 | 0.00438 | 1/6.9 |
| k_eff | 0.172 | 0.0661 | 1/2.6 |
| fp − fs 占 fs | 1.51% | 0.219% | 1/6.9 |
| C0 | 2.27 nF | 6.86 pF | 1/331 |

要点是：Janů 那只**还是空气耦合的传感器**，空气负载已经算极轻的负载，它的 Qm 也只有 43.4。
真实 PZT 的厚度模或长度模 k 约 0.4 到 0.5，串并联谐振间距应占 fs 的 8% 到 10%。

【模糊推测】一个负载良好的治疗性换能器，其 Qm 通常在 5 到 50 量级。这是文献中的典型范围，
不是本次针对该导管几何计算出来的。要给出本器件的确切负载 Q，
必须先完成 `docs/01` 第 9 步列的结构与声场求解。

### 4.3 弱耦合如何反过来让算法显得好

这一条是把 4.2 和第一节连起来，是本次审查比较要紧的一个观察。

本项目 `fp − fs = 1970 Hz`，而峰宽 FWHM = 1740 Hz，两者同量级。
**这意味着串联谐振峰和并联谐振谷几乎重叠成一个单峰。**

在真实耦合系数下，fp 和 fs 相距几十 kHz。±50 kHz 的粗扫窗口内会同时出现
一个功率极大点和一个很深的极小点。再叠加文献器件在 0.8 到 2 MHz 内的三个模态
（550 kHz 长度模基频、1095 kHz 径向模、1850 kHz 长度模三次谐波），功率频率曲线是**多峰**的。

而第 1.2 节里那条链，第 2 步「离真峰最近的栅格点就是粗扫最大值」，在多峰下不成立。
粗扫可能锁到一个次峰，精扫和超精扫再把它精修到次峰的顶点，整个过程看起来收敛得很漂亮。

**所以现有扫描显得稳健，有一部分来自耦合系数不真实。** 这是独立于搜索半径的第二个理由，
要求在参数改成真实值之后重新验证扫描策略，而不是把现在的 34 / 34 当作结论。

## 五、附带发现：30.14% 这个数字是双峰的

`stage5_integrated_strategy_table.csv` 里 FIXED_0P9 的 `steady_error_pct` 是 30.14。
复算逐段捕获情况（报表评估 `SCHEDULE[1:]`，即 7 段，含结尾那段 BASELINE）：

| 段 | 固定 0.9 MHz 得到 | 该场景最优 | 误差 |
|---|---|---|---|
| CASE_C0_P30 | 169.7406 mW | 169.9391 mW | 0.117% |
| CASE_RM_P50 | 159.1955 mW | 159.1955 mW | 0.000% |
| CASE_FS_M5 | 0.0426 mW | 140.2581 mW | 99.970% |
| CASE_LMATCH_P10 | 128.7864 mW | 144.8548 mW | 11.093% |
| CASE_QL_20 | 113.0537 mW | 113.1237 mW | 0.062% |
| CASE_COMBINED_HIGH | 0.0264 mW | 72.5605 mW | 99.964% |
| CASE_000_BASELINE | 170.0000 mW | 170.0000 mW | 0.000% |

7 段平均 30.17%，与报表的 30.14 对得上，差异来自尾窗取样。

**但这个平均值掩盖了真实形态。** 分布是双峰的：2 段接近 100% 误差，4 段低于 1% 误差，
只有 1 段落在中间。固定频率驱动不是「平均差 30%」，而是**要么基本无损，要么彻底丢失换能器**。

写报告时应当报告分布而不是均值，比如「7 段中 2 段完全失锁」。
均值 30.14% 会让读者以为固定频率只是效率低一些，而实际含义是在 2 个场景里功率掉到千分之三。
这也印证了 `docs/03` 那条警告：稳态误差统计必须说明口径。

## 六、模糊推测清单

本文及 `04` 中所有属于本次审查自行估计、不能作为参数依据的内容，汇总如下。

1. **导管 C0 约 330 到 770 pF。** 文献给了几何和材料，没有给 C0。
   我按径向极化空心圆柱、内外表面电极，用同轴电容公式
