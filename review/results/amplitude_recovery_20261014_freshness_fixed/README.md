# 幅度恢复门控对照批次（2026-10-14，已修时效性缺陷）

本目录取代 `review/results/amplitude_recovery_20261013/` 的四个 `L3 重冻结 *` 变体。
由同一脚本在修正后生成：

```
python review/amplitude_recovery_study.py --root <unified 源目录> \
       --out review/results/amplitude_recovery_20261014_freshness_fixed
```

脚本默认只读；只有显式给 `--out` 才落盘，且拒绝写入任何 `workspace/` 或 `outputs/` 路径。

## 修了什么

2026-10-14 的外部审核指出 `run_hybrid` 在扫描成功后刷新了相位目标 `tp` 却没刷新 `last`，
于是 `probe_update` 用扫描前、旧中心的测量算误差，却围绕新中心布置探针。复算成立：
全程 33 次，其中 19 次误差超死区而真正进入探针流程。
`hold=True` 时恢复门控恰好挡住了这条路径，使门控看起来值 +11.75 pp。

本轮改动三处，都在 `review/amplitude_recovery_study.py` 的 `run_hybrid` 内：

1. 捕获成功时 `last = pt.measurement`——捕获点本身就是新中心上最新的测量。
2. 捕获失败时 `tp, last = None, None` 并记 `PHASE_TARGET_REVOKED`：
   旧目标属于一个已经离开的频率，不得继续据以调频，须等下一次有效捕获。
3. 新增 `STALE_CENTRE_MEASUREMENT_BLOCKED` 护栏：
   `probe_update` 之前检查 `last.frequency_Hz` 与可信中心是否一致，不一致就不探。

保护器、增益、死区、段长、时钟、幅度门控逻辑与评分器均未改动。

## 护栏是否改变了结果

没有。护栏在四个 L3 变体里分别触发 6 / 18 / 36 / 36 次，
但被挡的样本保护状态**全部是 `FOLDBACK`**，而 `probe_update` 的第一个检查
（`m.state != 'NORMAL'`）本来也会提前返回。所以它只是把这个条件显式化并记进事件流，
数值与只做第 1 项修改的结果逐位相同（这一点与外部审核的一行诊断互为印证）。

## 撤权路径的故障注入

正常运行中 `PHASE_TARGET_REVOKED = 0`，即第 2 项修改在本日程上**从未执行**。
为避免交付未经执行的代码，另做了一次注入：把每个 `PHASE_TARGET_CAPTURE` 点强制判为无效，
结果 15 次撤权、0 次重冻结、0 次相位更新，达标 7/12、能量 43.344211%、实际硬越限 0.000 ms。
策略降级为"扫描捕获 + 定频满幅"而不崩溃、不越限。
该注入是一次性检查，未落盘；复现方式记录在 `review/21` §3.2。

## 先核基线再比数字

`provenance.json` 的 `source_hashes` 与已登记批次
`UNIFIED_20260923T013352_476445Z_f442bcda` 的 `run_metadata.json` → `source_hashes` 逐条相同。

`metrics.evaluate(rows, events, cfg, metrics.references(cfg))`；
参考功率是 100 Hz 网格上 `p_rm_W·a²` 的峰值，`a = min(1, Vsoft/Vport, Isoft/Iport)`。

**自证条件：`A 原样 (死区 0.10°)` 必须是 6/12、57.337359%。**
