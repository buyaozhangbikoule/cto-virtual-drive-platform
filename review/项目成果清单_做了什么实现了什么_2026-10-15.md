# 项目成果清单：做了什么东西，实现了什么功能

2026-10-15。按"从器件模型到验收体系"的层次梳理，每层写清**做了什么**、**能做到什么**、
**不能说的是什么**。数字都取自仓库，可复算。

边界先说在前面：**全部是基于假设 BVD 参数的电学准稳态仿真。非实测换能器、非完整功放、
非声学或临床验证。** 下面所有"功能"都指在这个模型里成立。

---

## 第 1 层：电学模型

**做了什么**

- BVD 等效电路（C0 并联在 Rm/Lm/Cm 支路上）+ 有损 L 型匹配网络 + 戴维南源的解析模型，
  `models/model_v2_1.py`，374 行。
- 匹配网络的损耗按声明的 Q 折算成频率无关的 ESR：`r_l = 2πf₀L/Q_L`、`r_c = 1/(2πf₀C·Q_C)`。
- **34 项扰动场景登记表**，12 个族 × 各 3 档 + 基准：
  C0、Rm、fs、Lm、Cm、Rs、匹配电感、匹配电容、电感 Q、机械 Q、三档组合扰动。

**实现了什么功能**

给定频率、场景、驱动幅度，一次调用返回完整的电学状态：
`Z_bvd`、`Z_in`、端口电压/电流、输入端相位 `arg(Z_in)`、机械支路功率 `p_rm_W`、
源功率、各损耗支路、功率平衡残差、反射代理 Γ。

这是后面所有东西的地基——选频、控制、保护、评分都从这里取数。

**不能说的**

34 个登记项**不是 34 个不同的物理状态**。本轮查出其中
`CASE_000_BASELINE`、`CASE_QL_100`、`CASE_QM_800` 三项的 BVD、匹配与源阻抗**完全相同**，
所以实际是 **32 个唯一物理状态、31 个唯一非基准扰动**。
统计覆盖度时要用去重口径，不能把别名当新增覆盖。

## 第 2 层：跨工具验证（Python ↔ LTspice）

**做了什么**

- LTspice 桥接 `scripts/ltspice_bridge.py`、闭环接口 `scripts/ltspice_closed_loop.py`。
- 仓库里有 **181 个** `.asc/.net/.raw/.cir` 文件（网表、原理图、求解结果）。
- 同源条件下的 Python/LTspice 静态交叉对照。
- LTspice 真实求解的历史指令瞬态重放（含步长核查、RAW、日志、截图、尾段对照）。
- 固定负载、低幅条件下的**五轮真实反馈接口检查**——第 5 轮执行了第 4 轮的反向决策，
  证明反馈链路真的闭上了。

**实现了什么功能**

同一组参数在两套独立工具里算出同样的结果——**12 个场景全部 PASS**
（这一条经 `review/17` 的合规性审查独立核过）。
这是"模型没写错"的主要证据，也是这个项目里为数不多的**跨工具**验证。

**不能说的**

瞬态重放是**固定 fs−5% 负载的开环片段**，不含 2.4 s 的负载突变，不是完整三策略闭环。
五轮反馈是固定基准负载、低幅、离线接口，**不证明动态扰动跟踪、连续稳态或全过程硬保护**。

## 第 3 层：选频与扰动分析

**做了什么**

- 三种选频判据的同口径对照：最大功率、最小 |相位|、最小反射代理。
- 扫频窗口与步长的权衡分析（±20/±50/±100 kHz 热图）。
- 相位闭环的增益扫描。
- 单因素与组合扰动下的峰值漂移趋势。

**实现了什么功能**

回答了"按什么判据选工作频率"这个问题，并且**量出了三种判据不重合**。
最有价值的一条是本轮做实的：

> 冻结的绝对相位目标 `arg(Z_in) = −1.078°`（在基准负载 900 kHz 标定）
> 在 **9 个场景里有 5 个**于功率最优点附近**无解**——误差 38°–85°，±3 kHz 内不变号。

这不是"没调好"，是判据本身在那些负载下不可用。文献上也是已知的：
零相位点 ≠ 谐振点（并联电容把它移开），相位判据是负载相关的，PLL 还会锁到反谐振。
我们在约 902 kHz 处确实找到了那个反谐振解。

**不能说的**

三个最优点不重合，所以**不存在一个"自然"的正确判据**；选哪个是设计决定，不是物理必然。

## 第 4 层：控制与保护（这是核心工程量）

**做了什么**

`unified/` 下 4 个文件共 1243 行，是整个项目的控制内核：

| 文件 | 行数 | 职责 |
|---|---|---|
| `engine.py` | 267 | 执行器 + 保护状态机 + 时间记账 |
| `controllers.py` | 432 | 三级扫描、相位更新、三个正式策略、故障分类 |
| `metrics.py` | 170 | 验收判定、能量积分、参考最优 |
| `models/model_v2_1.py` | 374 | 被控对象 |

具体实现的机制：

1. **三级局部扫描**：±50 kHz/5 kHz → ±5 kHz/1 kHz → ±1 kHz/100 Hz，每级 3 次重定位，
   每级结束实测锚点，细级碰边先实测再有界回退。
2. **保护状态机**：NORMAL / SOFT_FOLDBACK / HARD_TRIP / HOLD / RECOVERY / RAMP_UP /
   PREPARE / FOLDBACK，软限 130 Vpp / 5.5 mA、硬限 160 Vpp / 6 mA，
   硬保持 60 ms、恢复保持 100 ms、斜升 2.5/s。
3. **统一执行器**：控制动作、扫描点、相位探针**全部走同一条保护链**，
   没有任何动作能绕过保护或不计时间。这一条是这个项目最该强调的工程纪律。
4. **三个正式策略**：固定频率、周期扫频、相位反馈；P&O 作为第四种扩展单列。
5. **控制器隔离**：策略**看不到**场景 ID、扰动日程、离线最优表、验收计数——
   只能通过 `Executor` 读自己的测量。这是可以被机械检查的（本轮对候选做过全文扫描，零命中）。
6. **扫描故障四分类**：搜索失败 / 保护抢占 / 数据故障 / 非平稳，四类预算分开记账、
   共用一个显式复位锁存。

**实现了什么功能**

能在 12 段 × 0.8 s 的扰动日程上，让三个策略在同一保护链下跑完，
逐动作记录频率、幅度、保护状态、端口量、功率，并产出可逐行核对的执行表与事件流。

这个分类机制解决过一个真问题：`review/13` 之前，一次段边界的保护跳闸被记成"扫描算法失败"。
加上分类后，在 (周期 × 相位) 41 组网格里**搜索失败为 0**——原先记作扫描失败的全部是
保护抢占或被控对象在扫描中途改变。

**不能说的**

保护是在**准稳态样本**上生效的。"实际硬越限时长 0.000 ms"只说明采样点上没越限，
**不证明采样间隙和载波瞬态安全**。

## 第 5 层：评价与验收体系

**做了什么**

- 统一评分器：CONTROL 样本、NORMAL、未冻结、测量有效、捕获 ≥98%、
  20 ms 格点上**连续 10 个样本**（= 200 ms）才算该段达标。
- 参考最优用**软约束可行功率**：`max(p_rm_W · a²)`，`a = min(1, V软/Vport, I软/Iport)`，
  在 100 Hz 网格上取峰——不是裸功率。
- 同时报：逐段达标、全程电能捕获率、保护前预测电压/电流峰值、实际越限时长、
  最差段、逐场景是否退步。
- 批次哈希追溯：`run_metadata.json` 记录源码逐文件 SHA256、Python/NumPy 版本、
  完整命令行。
- **41 项正式行为测试**。

**实现了什么功能**

任何一个候选都能被放进同一口径里打分，并且**能证明它跑的是哪份源码**——
本轮所有复算都靠这个：我方源码哈希与已登记批次
`UNIFIED_20260923T013352_476445Z_f442bcda` 逐条相同，所以数字可比。

还有一条配套纪律：**不用后续成绩覆盖旧结果**。失败批次、带缺陷的批次全部保留并加作废标注。

**不能说的**

哈希只证明快照完整，**不证明物理正确**。另外实测发现该实现**不是逐次可复现的**：
同机同版本连跑两次，执行表有末位浮点差（≤2.4e-16，不改变任何判决），
所以回验必须用容差比较器，不能逐字节比对。

## 第 6 层：平台界面与可追溯性

**做了什么**

- Streamlit 应用 `streamlit_app.py` + LTspice 闭环验证页。
- 参数来源追溯 UI `provenance_ui.py`、`parameter_sources.py`——
  每个参数能点开看来源分类（假设值 / 文献 / 设计计算）。
- 产物登记表 `artifact_registry.json`、交付清单 `delivery_manifest.json`。
- 电声接口导出 `export_electro_acoustic_interface.py`（标准电学接口 + 空模板，
  为将来接声场求解留的口）。
- 交接体系：`handoff.py`（准备工作副本、校验）、分块归档与 SHA256 清单、
  `GIT_CONTENT_INDEX.json` / `GIT_OMISSIONS.json` 说明哪些文件在 Git 里、哪些只在 Release 里。

**实现了什么功能**

别人接手时能知道每个数字从哪来、哪些是假设、哪些经过验证，
并且能用 `handoff.py prepare` 建工作副本而不污染历史快照。

**不能说的**

声场接口只有**字段定义和空模板**。结构、材料、边界、网格、模态、谐响应、声压求解
**一样都没做**。

## 第 7 层：审查与复算体系（近一个月的主要产出）

**做了什么**

`review/` 下 **21 份审查文档 + 19 个只读复算脚本**。规矩是：

- 每个结论配一个**只读**脚本，默认不落盘，拒绝写入 `workspace/` 或 `outputs/`。
- 每个脚本有**自证条件**——比如"正式相位策略必须跑出 6/12、57.337359%"，
  跑不出就说明基线或口径不对，后面数字一律不作证据。
- 发现错误就地标注〔已改正〕，**不删旧结论、不覆盖旧结果**。

**实现了什么功能**

这套体系实际抓出了一批真缺陷，包括我自己写的：

| 缺陷 | 后果 |
|---|---|
| 朴素 Struve 级数在 x≈49 给出 −3934（真值 0.638） | 程序输出错数还打印"全部断言通过" |
| 辐射电阻自洽模式的频率因子错了 | 钙化流体代理 ΔQm 从 −0.03% 变成 +6.67% |
| 我的自检断言是**同源的恒等式** | 注入 k∈{0.5,…,10} 都能通过，永远抓不到错 |
| 复算脚本把相位目标传成 0.0（真值 −1.0782°） | 外部审核查出 |
| 去嵌表声称"只用标称值"，代码却读了真值 | 达标场景数虚高 4/9 → 实为 3/9 |
| 我的恢复门控不清 `a_prev` | 把"幅度下降"误判为"已稳定"，还被我当成了算法优势 |

**最后那条值得单独讲**：我做的一个版本比另一个多 1 个达标段，我据此写了"我的方案更优"。
后来查出来那 1 段只差**一个 20 ms 格点**，而且是我自己代码的缺陷造成的。
修掉之后两版数字**逐位相同**——本来就是同一个算法。

**不能说的**

审查体系抓到的是**已经去找的那些**。它降低了"输出错数字还自称通过"的概率，
但不构成正确性证明。

## 当前成绩（12 段历史日程）

| 策略 | 达标段 | 全程电能捕获 |
|---|---|---|
| 固定频率 | 7/12 | 73.78% |
| 周期扫频 | 1/12 | 41.96% |
| 相位反馈（正式） | 6/12 | 57.34% |
| 相位反馈 + 幅度恢复门控（候选，未推广） | 7/12 | **70.10%** |

本轮查清的两件事：

1. **周期扫频的 1/12 不是搜索不行**。9.6 s 里 76.9% 的时间不在满幅，4739 ms 在升幅，
   真正搜索只占 1961 ms。最说明问题的是第 0 段——基准场景、起点就在最优频率、
   20 ms 就拿到首个合格样本，**能量却只有 75.0%**，缺掉的 25% 全是扫描自己的开销。
2. **相位反馈的 6/12 有两个独立原因**：4 个段是判据无解（第 3/6/8/10 段永远 0.0%），
   其余几段是保护器的幅度棘轮——`min(old_a, wanted)` 配上每拍三次改频，
   使幅度只能降不能升。第 7 段因此在频率已收敛到 99.9996% 潜力的位置上只拿 61.3%，
   **而日志显示状态 NORMAL**。修这一条值 +12.8 个百分点。

## 明确没有做的

照搬 `docs/01_项目状态与下一步.md` 的口径，加上本轮的：

- 统一全场景闭环验收（34 场景的正式三策略排名）。
- 动态负载反馈——当前所有场景都是**分段常数**，没有段内连续变化的负载。
- 全过程／采样间隙的硬约束证明。
- 结构—声场求解（ANSYS/COMSOL）：几何、材料矩阵、极化、边界、网格一样没有。
- 真实器件阻抗、功率、水听器声场的任何实测。
- 本轮的候选（幅度恢复门控、±20 Hz 探针）**都没有接入正式三策略**，
  也没有走"开发 → 冻结 → 检验"的分离流程。
